# Налаштування Aerial Danger

Aerial Danger аналізує текстові повідомлення про повітряні загрози та створює відповідні сутності у Home Assistant. Інтеграція не отримує повідомлення самостійно — їй потрібні інші сутності, стан яких містить текст для аналізу.

> [!CAUTION]
> Інтеграція може помилятися, пропускати повідомлення або виявляти їх із запізненням. Не використовуйте її як єдине чи офіційне джерело сповіщень. Завжди стежте за офіційними сповіщеннями та виконуйте їхні вказівки.

У цьому прикладі джерелами повідомлень будуть сенсори інтеграції [Scrape](https://www.home-assistant.io/integrations/scrape), які читають останні дописи публічних Telegram-каналів.

## 1. Створіть Scrape-сенсор для Telegram

Підходять лише публічні канали, доступні у браузері без авторизації. Наприклад:

- [Повітряні Сили ЗСУ](https://telegram.me/s/kpszsu)
- [War Monitor](https://telegram.me/s/war_monitor)
- [Aeris Rimor](https://telegram.me/s/AerisRimor)
- [Оперативний інформ](https://telegram.me/s/operinform)
- [Kyiv Air Defence](https://telegram.me/s/kyiv_airdef) — лише Київ

[![Додати інтеграцію Scrape][scrape-install-image]][scrape-install-url]

1. Відкрийте **Налаштування → Пристрої та служби → Додати інтеграцію** та виберіть **Scrape**.
2. Створіть ресурс із URL каналу у форматі `https://telegram.me/s/CHANNEL`, наприклад `https://telegram.me/s/war_monitor`.
3. У створеному записі Scrape додайте сенсор із такими параметрами:

   | Параметр        | Значення                                              |
   | --------------- | ----------------------------------------------------- | ---- | ----------------------------------- |
   | Назва           | Наприклад, `Telegram — War Monitor`                   |
   | CSS-селектор    | `.js-widget_message_wrap:last-child .js-message_text` |
   | Шаблон значення | `{{ value                                             | trim | truncate(255, end='', leeway=0) }}` |

Шаблон прибирає зайві пробіли та обмежує стан сенсора до 255 символів — максимальної довжини стану сутності Home Assistant.

Повторіть ці кроки для кожного потрібного каналу. Один канал створює одну окрему сутність, наприклад `sensor.telegram_war_monitor`.

### Перевірте сенсор

Відкрийте **Інструменти розробника → Стани**, знайдіть створену сутність і переконайтеся, що її стан містить текст останнього допису каналу. Якщо стан порожній або `unavailable`, перевірте URL, CSS-селектор і доступність каналу у браузері.

## 2. Оновлюйте Scrape-сенсори кожні 5 секунд

Scrape за замовчуванням опитує ресурс кожні 600 секунд. Щоб примусово оновлювати сенсори частіше, створіть автоматизацію:

1. Відкрийте **Налаштування → Автоматизації та сцени**.
2. Натисніть **Створити автоматизацію → Створити нову автоматизацію**.
3. Відкрийте меню автоматизації, виберіть **Редагувати в YAML** і вставте цей шаблон:

```yaml
alias: Оновлення Telegram-сенсорів кожні 5 секунд
description: Примусово оновлює джерела повідомлень для Aerial Danger
triggers:
  - trigger: time_pattern
    seconds: "/5"
conditions: []
actions:
  - action: homeassistant.update_entity
    target:
      entity_id:
        - sensor.telegram_war_monitor
mode: single
max_exceeded: silent
```

Замініть `sensor.telegram_war_monitor` на фактичний ідентифікатор свого сенсора. Для кількох каналів додайте всі сутності до списку:

```yaml
entity_id:
  - sensor.telegram_war_monitor
  - sensor.telegram_kpszsu
  - sensor.telegram_aeris_rimor
```

Збережіть автоматизацію та запустіть її вручну один раз для перевірки. Коли Telegram опублікує новий текст, стан сенсора в розділі **Інструменти розробника → Стани** має змінитися без очікування стандартних 10 хвилин.

> [!IMPORTANT]
> Інтервал 5 секунд створює до 12 запитів за хвилину для кожного каналу. Telegram може обмежити частоту запитів або тимчасово заблокувати їх. Якщо сенсор стає `unavailable`, збільште інтервал до 10–30 секунд. Не використовуйте більше каналів, ніж потрібно.

## 3. Налаштуйте Aerial Danger

1. Відкрийте **Налаштування → Пристрої та служби → Додати інтеграцію**.
2. Знайдіть **Aerial Danger** і почніть налаштування.
3. На першому кроці вкажіть:
   - **Назва** — назва запису моніторингу та створеного пристрою;
   - **Джерела повідомлень про загрози** — один або кілька створених Scrape-сенсорів.
4. На кроці **Регіони** виберіть готові регіони, додайте власні регулярні вирази або поєднайте обидва варіанти. Регіони використовуються для виявлення балістичних, крилатих ракет та інших швидких загроз.
5. На кроці **Місцевості** виберіть свою та сусідні місцевості. Вони використовуються для виявлення дронів та всіх інших типів загроз.
6. Завершіть налаштування. Потрібно вибрати щонайменше одне джерело та один регіон або одну місцевість.

Після налаштування інтеграція створить:

- окремі бінарні сенсори для балістичних ракет середньої дальності, балістичних і крилатих ракет, дронів та невідомої загрози;
- загальний бінарний сенсор **Небезпека**;
- сутність подій **Виявлено небезпеку**.

Перевірте створені сутності на сторінці пристрою Aerial Danger. Коли стан джерела зміниться і новий текст відповідатиме обраній території та типу загрози, відповідний бінарний сенсор увімкнеться, а сутність подій зафіксує нове виявлення.

Щоб змінити джерела, регіони або місцевості, відкрийте запис Aerial Danger і виберіть **Налаштувати**. Для різних територій або груп каналів можна створити кілька окремих записів інтеграції.

## 4. Надсилайте критичне сповіщення про небезпеку

Цей приклад надсилає критичне сповіщення на iPhone через офіційний застосунок Home Assistant, коли загальний бінарний сенсор **Небезпека** переходить у стан `on`:

```yaml
alias: Критичне сповіщення про повітряну загрозу
description: Сповіщає, коли Aerial Danger виявляє небезпеку
triggers:
  - trigger: state
    entity_id: binary_sensor.aerial_danger_danger
    to: "on"
conditions: []
actions:
  - action: notify.mobile_app_your_phone
    data:
      title: Повітряна загроза
      message: >-
        {{ state_attr('binary_sensor.aerial_danger_danger', 'matched_area') }} —
        {{ state_attr('binary_sensor.aerial_danger_danger', 'matched_message') }}
      data:
        push:
          interruption-level: critical
mode: single
```

Замініть:

- `binary_sensor.aerial_danger_danger` — на фактичний ідентифікатор загального сенсора **Небезпека**;
- `notify.mobile_app_your_phone` — на дію сповіщень свого телефона з розділу **Інструменти розробника → Дії**.

Для Android використайте ту саму автоматизацію, але замініть блок `actions` на цей:

```yaml
actions:
  - action: notify.mobile_app_your_phone
    data:
      title: Повітряна загроза
      message: >-
        {{ state_attr('binary_sensor.aerial_danger_danger', 'matched_area') }} —
        {{ state_attr('binary_sensor.aerial_danger_danger', 'matched_message') }}
      data:
        ttl: 0
        priority: high
        channel: alarm_stream
```

На Android канал `alarm_stream` відтворює звук через потік будильника навіть у беззвучному режимі. На iOS рівень переривання `critical` дозволяє сповіщенню відтворити звук у беззвучному режимі та режимі «Не турбувати». Перевірте дозволи на критичні сповіщення у налаштуваннях телефона.

### Порада: перевіряйте, чи ввімкнена повітряна тривога

Щоб зменшити кількість хибних сповіщень, додайте офіційну інтеграцію Home Assistant [Ukraine Alarm](https://www.home-assistant.io/integrations/ukraine_alarm/), виберіть свій регіон і знайдіть створений нею бінарний сенсор **Air**.

У наведеній вище автоматизації замініть блок `conditions` на такий:

```yaml
conditions:
  - condition: state
    entity_id: binary_sensor.air_alert
    state: "on"
```
